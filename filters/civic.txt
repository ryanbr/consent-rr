! Title: consent-rr - Civic Cookie Control
! Description: Replaces Civic's cookieControl-9.x.min.js with a stub that
!              reports a refusal, instead of waiting for a banner.
! Expires: 7 days
! Homepage: https://github.com/ryanbr/consent-rr
!
! These filters do nothing on their own: the resources they name have to be
! installed through uBlock Origin's userResourcesLocation setting first. See the
! README.

! -----------------------------------------------------------------------------
! Every optional category refused, the necessary ones untouched.
!
! One line covers both spellings of the same file: cookieControl-9.x.min.js and
! the pinned cookieControl-9.11.1.min.js beside it.
!
! Version 8 is deliberately not matched. It is a different, much smaller build,
! and this resource was written against 9 - a stub that answers for an API it
! has not been read against is how a page breaks quietly.
! -----------------------------------------------------------------------------
||cc.cdn.civiccomputing.com/9/cookieControl-9*.js$script,redirect=civic-reject.js

! -----------------------------------------------------------------------------
! Where a redirect cannot land.
!
! A user resource is served as a data: URI, so a site whose CSP omits data: for
! scripts refuses it - nothing of ours runs, no cookie, no console line, while
! the banner is gone anyway because the redirect kept the real script out. The
! scriptlet form is injected rather than fetched, so the directive does not apply
! to it. Both lines are needed on such a site:
!
! example.com##+js(civic-reject)
!
! The scriptlet has to be in place before the page calls CookieControl.load(),
! which it does inline, so this is one to pair rather than substitute.
! -----------------------------------------------------------------------------

! -----------------------------------------------------------------------------
! Sites that withhold content behind a category.
!
! Refusing is the point, but a site may gate its videos, maps or embeds on one
! of its own categories and show a placeholder until that category's onAccept
! has run - "We cannot show you this content because it uses cookies" and the
! like. The category is the site's own, so no resource can know its name: name
! it in the filter instead, and the redirect above keeps doing the rest.
!
! Up to three names, and * for all of them. The name is the one the site's own
! CookieControl.load() call uses, which the console line prints.
!
! Arguments only reach the scriptlet form. Where one line is wanted instead,
! civic-reject-unblock.js does the same for every category the site declares,
! as a redirect - point it at the sites that need it, and raise its priority
! above the rule below, which matches the same request:
!
! ||cc.cdn.civiccomputing.com/9/cookieControl-9*.js$script,redirect=civic-reject-unblock.js:10,domain=example.com
!
! It accepts the lot, so prefer naming the one category where that will do:
! Goldsmiths gates its videos and maps on "embedded", and its analytics stays
! refused this way.
! -----------------------------------------------------------------------------
gold.ac.uk##+js(civic-reject, embedded)

! -----------------------------------------------------------------------------
! The script is what asks for these, so with it replaced they are never
! requested. They only matter where something unblocks it: the API key and geo
! check it will not start without, the consent it logs back, and the IAB vendor
! list and purpose translations its TCF mode fetches.
! -----------------------------------------------------------------------------
||apikeys.civiccomputing.com^$xhr,redirect=noopjson
||clapi.civiccomputing.com^$xhr,redirect=noopjson
||cc.cdn.civiccomputing.com/vl/*$xhr,redirect=noopjson
